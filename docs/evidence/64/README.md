# Живой прогон #64 — несёт ли поток текстовую дорожку

Портативная сборка этой машины (Windows 10.0.19045 x64): `bun run tauri:win build --no-bundle` →
`python scripts/package_portable.py` → `dist_portable/aniplayer.exe`, sha256
`ec0e89457baa35b340c282af2a5a309b…`. Управление и запросы к живому webview — remote-debugging-port
WebView2 (9224) через `../62/cdp_events.ps1`; скриншоты — `../60/win32.ps1 -Action shot`.

Порядок такой не для порядка: [ADR 0017](../adr/0017-no-subtitle-control-the-catalog-delivers-no-text-track.md)
отказывается от субтитров как от фичи, и отказан он на замере, а не на мнении. Текстовая дорожка
может прийти в webview ровно двумя путями — WebVTT-ренди션, объявленная в плейлисте, или CEA-608
внутри видеопотока. Каждый путь замеряется своим скриптом по одному и тому же образцу каталога;
третий вопрос задаёт уже настоящий плеер.

## 1. Что объявляют плейлисты — `catalog_probe.py` (`catalog-01.txt`)

25 релизов, разбросанных по всему диапазону id, который каталог занимает (9525…10365). Из каждого
— по три серии (у части релизов серий меньше, поэтому сошлось 71 серия), каждой серии — все три
тира: 213 плейлистов, 213 × 3 = 30 667 URI сегментов.

```
{"releases":25,"playlists":213,"tiers_declared":213,"tiers_absent_from_the_episode":{},
 "playlist_kind":{"media":213},
 "tags":{"EXTINF":30667,"EXTM3U":213,"EXT-X-VERSION":213,"EXT-X-TARGETDURATION":213,
         "EXT-X-MEDIA-SEQUENCE":213,"EXT-X-PLAYLIST-TYPE":213,"EXT-X-ENDLIST":213,
         "EXT-X-INDEPENDENT-SEGMENTS":156},
 "codecs_attribute":{},"playlists_naming_a_text_track":[],"playlists_unreachable":0,
 "releases_skipped":[10309,10253,10197,9861,9693],
 "torrent_hardsub_census":{"is_hardsub=False":31,"is_hardsub=True":18}}
```

Это полный набор HLS-тегов, который каталог вообще использует. Ни одного `#EXT-X-STREAM-INF`: все
213 — Media Playlist. Тега, которым объявляется рендиция, — `#EXT-X-MEDIA:` — нет нигде;
`EXT-X-MEDIA-SEQUENCE`, который начинается с тех же букв и есть в каждом плейлисте, к тексту
отношения не имеет. Ссылок на `.vtt`/`.srt` — ноль, `CODECS=` — ноль.

RFC 8216 §4.3.4 относит `#EXT-X-MEDIA` к Master Playlist tags и запрещает таким тегам появляться
в Media Playlist, а API отдаёт плееру именно Media Playlist тира. Объявить сегментированную
субтитр-рендицию в той форме, которую раздаёт CDN, негде.

`is_hardsub` (18 true / 31 false по торрентам тех же релизов) — единственное место в модели
каталога, где слово «субтитры» существует вообще. Мягкие дорожки живут в `.mkv` торрента, который
[ADR 0013](../adr/0013-hls-only-delivery-drops-bittorrent.md) вывел из продукта; у HLS-тиров поля
про субтитры нет.

## 2. Что лежит внутри сегментов — `cea608_probe.py` (`cea608-01.txt`)

Те же 25 релизов, что и в цензе (`--releases-from catalog-01.txt`): по одной серии с каждого, два
тира (1080p и 720p), по одному сегменту из середины — 50 сегментов, 139,3 МБ, из них 121,5 МБ
видеопотока, все прочитаны целиком (`segments_read_in_full: 50`), разобранны до elementary streams
и NAL-единиц.

```
pmt_stream_types: {"0x1b AVC": 50, "0xf AAC-ADTS": 50}
avc_nal_types:    {"0x9": 12331, "0x7": 343, "0x8": 343, "0x5": 343, "0x1": 11988}
sei_payload_types: {}   itu_t_t35_signatures: {}   cea608_ga94_messages: 0
```

PMT каждого сегмента объявляет ровно два потока — видео и звук: ни ATSC A/52 (`0x06`, отдельный
PID под closed captions), ни metadata-потока, ни одного дескриптора. В видеопотоке нет ни одной SEI
NAL-единицы (`0x06` при 11 988 нарезанных слайсах), поэтому путь CEA-608 в hls.js не запускается:
библиотеке нужно `user_data_registered_itu_t_t35` со страной `0xB5`, провайдером `0x0031`,
структурой `GA94` и user data type 3 — ровно этот заголовок она и ищет в `parseSEIMessageFromNALu`.

Самопроверка детектора обязательна, иначе «ноль» был бы свойством парсера, а не потока —
`selftest-01.txt` собирает GA94-сообщение побайтно и прогоняет его через тот же разбор:

```
{ "detector_fires_on_synthetic_ga94": true, "messages": 1 }
```

## 3. Живой плеер — `texttrack_probe.ps1` (`texttrack-01.txt`, `texttrack-02.txt`)

Настоящее воспроизведение портативной сборки, оба прогона запущены кликами мыши через CDP: карточка
каталога → «Воспроизвести эпизод 1». Замеряется то, что элемент реально несёт: `textTracks` и
`trackNodes` — `<track>`-ноды, которые hls.js добавляет в `<video>` сам (`createTrackNode`, тем же
способом, каким создаёт дорожку для CEA-608).

| прогон             | релиз                                                              | торренты            | выборка                      |
| ------------------ | ------------------------------------------------------------------ | ------------------- | ---------------------------- |
| `texttrack-01.txt` | «Я перевоплотился в гоблина, вопросы есть?» (10338), серия 1, 720p | `is_hardsub: false` | 6 снимков, 337,5 s → 487,6 s |
| `texttrack-02.txt` | «Отель для нелюдей 2» (10345), серия 1, 720p                       | `is_hardsub: true`  | 4 снимка, 2,3 s → 77,4 s     |

```
17:03:48 sample 1: currentTime=337,5 readyState=4 frame=1280x720 textTrackCount=0 trackNodes=[]
17:06:19 sample 6: currentTime=487,6 readyState=4 frame=1280x720 textTrackCount=0 trackNodes=[]
17:11:44 sample 1: currentTime=2,3   readyState=4 frame=1280x720 textTrackCount=0 trackNodes=[]
17:12:59 sample 4: currentTime=77,4  readyState=4 frame=1280x720 textTrackCount=0 trackNodes=[]
```

Кадр пуст в обоих прогонах — и в релизе, чьи торренты помечены мягкими субтитрами, и в том, чьи
помечены hardsub. Конфиг библиотеки при этом дефолтный: `enableWebVTT: true`,
`enableCEA708Captions: true`, `renderTextTracksNatively: true` — `renderer/retryPolicy.ts` их не
трогает. Кадры: `01-live-playback.png`, `02-hardsub-frame.png`.

## Честные детали

- urllib этой сборки Python не принимает цепочку TLS на одном бэкенде CDN («certificate has
  expired»), schannel — тот же самый URL — 200. Сегменты поэтому качаются через `curl`: замер
  обязан видеть те же байты, что видит webview, а не то, что пропускает чужое хранилище корней.
- Нумерация AniLiberty начинается между 8000 и 8800 (8000 → 404, 8800 → 200), и id внутри
  диапазона не плотные: пять кандидатов из разброса ответили 404 и записаны в
  `releases_skipped`, а не молча проглочены. Ни один плейлист финального ценза не оказался
  недоступен (`playlists_unreachable: 0`); в более ранних прогонах часть сегментов отвечала 500 —
  ротация бэкендов из [#62](https://github.com/shidot3m/aniplayer/issues/62) — и в финальной
  выборке таких мест уже не было.
- Первый вариант PMT-парсера дособирался до CRC и приписывал сегменту фиктивный третий поток
  (`0x2f` из 256 байт `0xFF`), а первый вариант тег-ценза срезал `EXTM3U` на `EXTM` и ловил
  «субтитры» в hex-именах сегментов. Обе ошибки исправлены до финальных замеров выше; их
  промежуточные выводы из дерева убраны, чтобы никто не прочитал их как результат.
- `02-hardsub-frame.png` — кадр без строки субтитров: в этот момент серии никто не говорит. Флаг
  `is_hardsub` описывает, как торрент-кодинг вшил дорожку, и по нему нельзя судить о конкретной
  секунде видео; на замер выше он не влияет, потому что меряется поток, а не картинка.
- Первый прогон продолжил просмотр с 337,5 s — в `dist_portable/data/` осталась история
  предыдущего прогона. Это видно по `currentTime` и ничего не меняет: дорожка измеряется на
  всём протяжении серии.

## Что этот прогон не доказывает

Ни один из двух путей не приводит текстовую дорожку в плеер на сегодняшнем каталоге. Но в дереве
нет кода, который умел бы её _потреблять_, поэтому живым прогоном проверена только отрицательная
половина: «поток ничего не даёт». Положительная — «если бы дал, плеер бы показал» — не проверена
ни на чём, и первым шагом ветки, описанной в ADR 0017, должен стать самодельный плейлист с
настоящей WebVTT-рендицией: каталог такого не даст.

И то же самое — про цену отказа. Для релизов с `is_hardsub: true` субтитры в кадре всегда. Для
остальной половины каталога мягкая дорожка осталась в торрент-_payload, а в HLS её нет: зритель,
которому нужны субтитры, их не получит ни у какого плеера на этом CDN. Отказ #64 фиксирует, что
приложение не может это исправить кодом, — и не делает вида, что проблемы нет.

## Итог

Отказ — [ADR 0017](../adr/0017-no-subtitle-control-the-catalog-delivers-no-text-track.md); там же
триггеры пересмотра (master-плейлист, `#EXT-X-MEDIA:TYPE=SUBTITLES`, `.vtt`/`.srt` в URI,
`stream_type 0x06` в PMT, `GA94`-SEI в потоке) и способ их проверить — ровно эти два скрипта:
минуты работы, тот же формат ответа.
